Verify our images

Check who signed the PacketWolf image before you run it. You need cosign 2.x or later. No Zyvor account and no key.

Status: signing is being switched on. The first signed release is pending. Until then cosign verify reports no signatures found for every published digest; that result means "not signed yet", not a problem with your setup. This page will say so here when the first signed release is out, and the release notes will list the signed digests.

What will be signed

WhatHowTells you
Signaturecosign signature, keyless, next to the image in the registryThis digest was signed by the Zyvor signing workflow
SBOMcosign attestation spdxjson (SPDX 2.3, syft), also a release fileEvery package in the image
Provenancecosign attestation slsaprovenance1 (SLSA v1), also a release fileWhich signing run attested the digest, for which declared source commit

Signing is keyless: no long-lived key exists. A short-lived GitHub token proves the workflow's identity to Sigstore, which issues a certificate valid for minutes; the signature is recorded in the public Rekor log. You verify two facts: the identity that signed and the issuer that vouched for it.

Expected identity

Certificate identityhttps://github.com/zyvorai/zyvor-packetwolf-site/.github/workflows/sign-image.yml@refs/heads/main
OIDC issuerhttps://token.actions.githubusercontent.com
Imageghcr.io/zyvorai/zyvor-packetwolf

1. Pin the digest

A tag can move; a digest cannot. Resolve once, then use the digest everywhere.

IMAGE=ghcr.io/zyvorai/zyvor-packetwolf
DIGEST=$(docker buildx imagetools inspect $IMAGE:latest --format '{{json .Manifest.Digest}}' | tr -d '"')
echo $DIGEST

2. Verify the signature

cosign verify $IMAGE@$DIGEST \
  --certificate-identity https://github.com/zyvorai/zyvor-packetwolf-site/.github/workflows/sign-image.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com

Never use --certificate-identity-regexp '.*' or drop either flag: that accepts a signature from anyone.

3. Read the SBOM

cosign verify-attestation $IMAGE@$DIGEST --type spdxjson \
  --certificate-identity https://github.com/zyvorai/zyvor-packetwolf-site/.github/workflows/sign-image.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  | jq -r '.payload | @base64d | fromjson | .predicate' > zyvor-packetwolf.sbom.spdx.json

The same file is attached to each signed release. Feed it to your scanner, for example grype sbom:zyvor-packetwolf.sbom.spdx.json.

4. Read the provenance

cosign verify-attestation $IMAGE@$DIGEST --type slsaprovenance1 \
  --certificate-identity https://github.com/zyvorai/zyvor-packetwolf-site/.github/workflows/sign-image.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  | jq -r '.payload | @base64d | fromjson | .predicate'

This is a SLSA v1 statement about a prebuilt image: it binds the digest to a signed, logged run. It does not claim a reproducible build.

5. Enforce it

Put verification in your deploy path. In a cluster, admit only signed images with a policy engine that supports cosign keyless verification (for example Kyverno verifyImages or the Sigstore policy-controller), using the identity and issuer above and an image reference pinned by digest.

If verification fails

  • no signatures found: that digest is not signed (see the status above, or an older release). Use a digest listed as signed in the release notes.
  • none of the expected identities matched: the signer is not the Zyvor signing workflow. Do not run the image; tell info@zyvor.dev.
  • Network errors: cosign must reach the registry and the Sigstore TUF root (tuf-repo-cdn.sigstore.dev). Air-gapped sites need a mirror of that root; ask your Zyvor contact.
